# Deploying on Cloudflare + Neon (free tier)

Two free services, neither needing a card:

| Piece | Service | Free allowance |
|---|---|---|
| Pages and the `/api/v1` surface | Cloudflare Workers | 100,000 requests/day, 10 ms CPU each |
| CSS, JS and the 34 car SVGs | Workers static assets | unmetered, never billed |
| Database | Neon Postgres | 0.5 GB storage, compute suspends when idle |

## One-time setup

```bash
npm install
npx wrangler login
```

Create a Neon project at <https://neon.tech> and copy the **pooled** connection
string — the host contains `-pooler`. The HTTP driver holds no connections open,
so Neon's compute suspends between requests, which is what keeps it free.

```bash
cp .dev.vars.example .dev.vars      # paste the connection string in
npx wrangler secret put DATABASE_URL
```

## Load the database

```bash
npm run db:migrate    # 4 tables
npm run db:seed       # the 18-car fleet
```

Both are idempotent. `npm run db:seed -- --force` clears and reloads.

`db/seed.sql` is **generated** from `app/seed.py`'s `FLEET`, so the fleet is
defined once. After editing it:

```bash
python scripts/export-fleet.py > db/seed.sql
npm run db:seed -- --force
```

## Run and deploy

```bash
npm run dev            # http://localhost:8787
npm test               # 82 JS tests
npm run test:python    # 70 pytest tests
npm run deploy         # https://velocity-drive.<subdomain>.workers.dev
```

## What the port had to reproduce, and how it is checked

Cloudflare runs JavaScript, not CPython, so the Flask app could not be wrapped —
its logic was ported. Three of those modules decide what a customer sees, so
none of them is trusted on inspection. Each is compared against the Python it
came from, over fixtures generated by the scripts in `scripts/`:

| Module | Checked against | What is compared |
|---|---|---|
| `worker/nlp.mjs` | `app/nlp.py` | tokenisation, IDF weights, the full search ranking and its scores |
| `worker/recommender.mjs` | `app/recommender.py` | every intent field, every signal, the ranking order, scores and reason strings, across 24 queries |
| `worker/services.mjs` | `app/services.py` | 240 quotes — 4 cars × 10 durations × 6 add-on sets — raw and rounded |
| `worker/template.mjs` | Jinja 3.1.6 | all 10 templates, byte for byte, across 16 context cases |
| `worker/index.mjs` | Flask's `url_map` | all 19 routes, same methods, no extras |

Regenerate the fixtures after changing either side:

```bash
python scripts/export-nlp-fixtures.py         > test/nlp-fixtures.json
python scripts/export-recommender-fixtures.py > test/recommender-fixtures.json
python scripts/export-services-fixtures.py    > test/services-fixtures.json
python scripts/export-template-fixtures.py    > test/template-fixtures.json
npm test
```

Three genuine mismatches came out of that process, all of them things a reader
would have noticed before a test did:

- **Python prints a float's decimal point.** A 5.0 rating reads `Rated 5.0/5`
  in Flask and would have read `Rated 5/5` here.
- **Python's `round()` is half-to-even, and rounds on the decimal expansion.**
  Scaling by a power of ten can destroy the deciding information: `2.675` is
  really `2.674999…`, so Python gives `2.67`, but `2.675 * 100` evaluates to
  exactly `267.5` and rounds to `2.68`. The match percentages on the concierge
  page come out of that rounding.
- **MarkupSafe escapes `"` as `&#34;`**, not `&quot;`.

## Two deliberate differences from the Flask app

- **Dates.** The Worker treats a calendar date as a `YYYY-MM-DD` string and does
  day-number arithmetic, rather than using `Date`. A Worker runs in UTC while the
  renter is in Dubai, and `new Date('2026-09-20')` is midnight UTC — after 20:00
  UTC a same-day pickup would be rejected as being in the past. `todayInDubai()`
  applies the UTC+4 offset.
- **Availability.** `availableFleet()` counts overlapping bookings for the whole
  fleet in one query. The Python issues one per car, which is free against local
  SQLite but an HTTPS round trip each against Neon.

## Staying inside the free tier

- Static asset requests do not count against the Workers daily limit; only the
  pages and `/api/v1` do.
- The TF-IDF index is built once per isolate with a 60-second TTL, and only the
  concierge endpoint and a car's "similar" list use it. Everything else does no
  ranking work at all.
- Neon suspends compute when idle and the HTTP driver keeps nothing open.
- The fleet is a few kilobytes against a 0.5 GB allowance.
- Nothing here turns on a paid Neon or Workers feature.

## Automatic commits

`scripts/autocommit.sh` commits and pushes as you edit:

```bash
./scripts/autocommit.sh                  # every 3+ changed lines, checked every 15s
THRESHOLD=10 INTERVAL=60 ./scripts/autocommit.sh
NO_PUSH=1 ./scripts/autocommit.sh        # commit locally only
./scripts/autocommit.sh --once           # single pass
```

## Running the original Flask app

Still works, on SQLite, independently of Neon:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python run.py            # http://127.0.0.1:5000
pytest -q                # 70 tests
```

Two modules in `app/` were missing from the repository as checked out and are
reconstructed: `app/__init__.py` (`create_app`, which was a 0-byte file, so
nothing could import it) and `app/api.py` (the twelve `/api/v1` endpoints the
front-end JavaScript calls and README.md documents). The test suite pinned down
their contract.
